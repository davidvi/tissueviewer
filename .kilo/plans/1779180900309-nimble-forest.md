# Plan: Save & Restore Transform Settings Per Slide

## Goal
Allow users to save the current transform settings (rotation, horizontal flip, vertical flip) for a slide. The backend should persist them in the existing per-slide sidecar JSON and return them via `/samples.json` so the transform is restored automatically when the slide is reopened.

## Context
- Transform is currently client-side only: `rotationAngle`, `flipHorizontal`, `flipVertical` live in `slideView.vue` local state (`client/src/views/slideView.vue:395-399`) and are reset on every slide switch (`slideView.vue:572-575`).
- Per-slide settings are already persisted via `POST /save/{location}/{file}` (`src/tissueviewer/routes/save.py:18-49`), which writes the whole JSON body to `{slide_stem}.sample.json` next to the slide.
- That sidecar is returned under `samples[].details` by `/samples.json` (`src/tissueviewer/routes/samples.py:17-28`, loaded in `src/tissueviewer/discovery.py:159-166`).
- The save endpoint accepts arbitrary JSON, so **no backend code change is strictly required** to persist a new field — but to make the contract explicit, we will document/test the new `transform` field on the backend side.

## Data shape
Add a `transform` object to the per-slide `details` sidecar:

```json
{
  "transform": {
    "rotationAngle": 0,
    "flipHorizontal": false,
    "flipVertical": false
  }
}
```

Default when missing: `{ rotationAngle: 0, flipHorizontal: false, flipVertical: false }`.

## Changes

### 1. Vuex state (`client/src/store/index.js`)
- Add three new properties to root state (mirroring `description`, `altName`, etc.):
  - `rotationAngle: 0`
  - `flipHorizontal: false`
  - `flipVertical: false`

### 2. Vuex actions (`client/src/store/modules/slideContent.js`)
- **Extend `loadSample` (lines 190-226)** to read `selectedSampleBuf.details.transform` and commit each value to Vuex (with the defaults above). Place near the existing `description` / `altName` hydration block.
- **Add new `saveTransform` action**, modeled on `saveChannels` (lines 76-103):
  - Read existing `state.samples[...].details`.
  - Override only the `transform` subobject from current Vuex state (`rotationAngle`, `flipHorizontal`, `flipVertical`).
  - `axios.post(`${baseUrl}/save/${location}/${name}`, data)`.
  - Optimistically update `state.samples[...].details.transform` so subsequent re-opens use the new value without a refetch.
- **Extend `saveDetails` (lines 46-53)** to also include the current `transform` so the existing Rename / Add-to-folder save preserves it (defensive — same approach the existing fields use).

### 3. SlideView component (`client/src/views/slideView.vue`)
- **Replace local data props** (lines 395-399 — `rotationAngle`, `flipHorizontal`, `flipVertical`) with `computed` getters/setters that read/write the Vuex state (pattern: `activatedSampleLocal` at lines 479-486). This keeps the existing template bindings (slider/inputs/switches at lines 160-234) unchanged.
- **Drop `resetTransform()` from the `selectedSampleNameLocal` watcher** (lines 572-575). `loadSample` will now hydrate the transform from `details`; the manual "Reset" button at line 178 still calls `resetTransform()` for explicit user resets.
- **Apply transform after slide loads**: in the `currentSlideLocal` watcher (lines 576-582), after `this.viewer.open(newValue)` and the existing `'open'` handler logic, call `this._pushTransform()` (or do it inside the existing `'open'` event handler) so the OSD viewport reflects the loaded values once the image is ready.
- **Add a "Save transform" button** in the Transform section of the settings panel (around line 232, after the flip toggles), wired to `this.$store.dispatch('saveTransform')`. Show only when `saveEnabled` is true (mirror the gating used for the existing Save buttons).

### 4. Backend (`src/tissueviewer/`)
- **No code changes required** — `/save/{location}/{file}` already writes arbitrary JSON, and `/samples.json` already returns the whole sidecar under `details`.
- Optional documentation: add a comment in `src/tissueviewer/discovery.py` near the sidecar load (lines 159-166) noting that `details.transform` is a recognized field, for discoverability.

### 5. Tests (`tests/test_app_smoke.py`)
- Extend the existing sidecar-save/load smoke test (lines 65-86) to include a `transform` payload, asserting it round-trips through `POST /save/...` and reappears under `samples[].details.transform` in `/samples.json`. This locks the contract even though no Python code changes.

## Backwards compatibility
- Existing slides without a `transform` field in their sidecar fall back to the default (`0 / false / false`), matching today's behavior.
- The Reset button continues to work for one-off resets (it only zeroes Vuex state; it does not save).
- Save is gated by `state.config.save_enabled` on both sides, same as existing save buttons.

## Out of scope
- No new backend route, no schema/migration (filesystem sidecar only).
- No changes to tile URL construction — transforms remain a client-side OSD viewport operation.
- No auto-save on every transform change; saving is explicit via the new button (matches the "Save channels" UX).
